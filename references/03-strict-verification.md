# Stage 3 — 严格验证与正式节点

只有完成必要拆分、来源追溯和反证检查后，才可建立正式问题节点。证据不足的候选继续保留在前两层，不得包装成确定事实。

## 正式节点 Schema

```markdown
问题 ID：[P-YYYYMMDD-XXXX]
关联候选线索：[C-...]
关联复核记录：[R-...]
问题标题：[具体操作失效或流程瓶颈，不用空洞行话]
所属行业：[宏观行业或领域]
细分领域：[业务细分或专业子方向]
问题类别：[受控词表中的一个主类别]
验证状态：[受控词表中的一个状态]
解决状态：[受控词表中的一个状态]

问题描述：[2–3 句；区分观察事实与机制解释]

现实工作流呈现：
- 步骤 1——输入或触发条件：
- 步骤 2——具体失效节点：
- 步骤 3——直接连锁反应：
- 步骤 4——下游负面后果：

受影响的利益相关者与影响不对称性：
- 核心遭遇者：
- 经济/财务承担者：
- 风险承担者：
- 决策控制者：

底层机制与动力学原理：[推断须加 `[假设]`]

现有权宜方案及其失效模式：
- 当前做法 / 权宜之计：
- 适用边界：
- 难以承受的代价 / 缺陷：

跨领域结构同构：[相同因果拓扑或数学动力学；推测须加 `[假设]`；没有则写“暂未识别”]

实证证据与审计追溯：
- 来源标识：[DOI、RFC/ISO/NIST、官方报告、监管文件、Bug 编号、可核验 URL，或“待核实”]
- 来源层级：[一级证据 | 二级证据 | 线索性材料]
- 支持内容：[来源实际支持什么]
- 不支持内容：[不能由来源推出什么]
- 相反证据：[来源或“尚未检索到”]
- 可量化影响半径：[成本、延误、报废率、错误率、事故率、人数等；未知写“待测定”]
- 验证说明：[可靠性、独立性、时效性和适用范围]
- 证据缺口：[仍需的日志、样本、访谈、实验或统计]

待解实证问题：
1. [可被观察或实验推翻的问题]
2. [可被观察或实验推翻的问题]

节点关系：
- 前置问题：[问题 ID | 待识别]
- 下游问题：[问题 ID | 待识别]
- 近似/重复节点：[问题 ID | 无]
- 冲突节点或反例：[问题 ID、来源 | 尚未识别]

节点变更记录：
- 创建日期：[YYYY-MM-DD]
- 当前版本：[版本号]
- 最近变更原因：[新增证据 | 状态变化 | 节点拆分 | 节点合并 | 证伪]
- 是否保留原始记录：是
```

若节点被证伪，更新验证状态并记录反证，不删除节点。
